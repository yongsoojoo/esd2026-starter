# 보고서 작성 가이드

규칙 파일 (`AGENTS.md`) 이 아니라 별도 가이드로 둡니다. 보고서를 쓰는 세션에서 에이전트에게 이 파일을 함께 읽힙니다.
보고서 본문은 회의록과 같이 「~함」 체로 씁니다.

## 1. 반복은 층마다 다르게

한 주장은 여러 곳에 나옵니다. 층이 깊어질수록 **정보가 늘어야** 하고 문장은 새로 써야 합니다.

| 층 | 무엇을 쓰나 |
|---|---|
| 요약 (초록) | 주장 한 구절 + 대표 수치 |
| 서론 | 주장 1~2 문장 + 결과가 뜻하는 것 |
| 본문 (설계 · 실험) | 정의 · 그림 · 조건 · 조건부 수치 — **여기에만** 둡니다 |
| 결론 | 주장만. 수치를 다시 늘어놓지 않습니다 |

- **같은 층의 중복이 낭비입니다**: 같은 사실이 같은 깊이 · 같은 역할로 두 번 나오면 하나로 합칩니다. 기준은 「두 번째가 새 정보를 더하는가」 입니다
- **대표 수치는 2~3 개**만 정해 요약 · 서론 · 결과에 **같은 값**으로 둡니다. 요약 · 서론은 반올림하고, 결과 절은 소수까지 씁니다

## 2. 분량은 결과입니다

- 「N 쪽으로 줄이기」 를 편집 목표로 삼지 않습니다. 처음부터 읽으며 같은 층의 중복을 지우면 분량은 따라 줄어듭니다
- 분량을 맞추려고 정보 (조건 · 한계 · 실패한 시도) 를 지우지 않습니다

## 3. 기호와 용어

- 기호 하나는 보고서 전체에서 한 뜻만 갖습니다. 새 기호를 쓰기 전에 기호표와 대조합니다
- 용어는 처음 나올 때 한 번 정의하고, 그 뒤에는 정의 없이 씁니다

## 4. 그림과 표

- 캡션에는 「무엇을 그렸나 + 실험 조건」 만 씁니다. 해석은 본문에 씁니다
- 모든 수치는 출처 (로그 파일 · 실험 기록) 로 거슬러 갈 수 있어야 합니다. 표 아래에 `logs/experiments/<파일>` 을 적습니다

## 5. 정정할 때

- 한 수치를 고치면 그 수치가 나오는 **모든 곳** (요약 · 서론 · 표 · 그림 · 결론) 을 `grep` 으로 찾아 함께 고칩니다
- 변경 표시 (색 · 취소선 매크로) 를 지운 뒤에는 컴파일 통과만 보지 말고 **렌더된 PDF 의 텍스트**를 이전 판과 비교합니다 —
  문장 일부가 주석 안으로 사라져도 컴파일은 통과합니다
- 정정은 작성한 세션과 다른 경로 (새 세션 · 다른 도구 · 지도교수나 조교의 피드백) 로 다시 확인합니다 (`AGENTS.md` §5-8)
