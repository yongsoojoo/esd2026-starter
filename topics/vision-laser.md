### 8-C. Vision-based object tracking + laser pointing (영상 → pan-tilt 서보 2 개 + 레이저)

**좌표 · 단위 (한 번 정하고 바꾸지 않습니다)**
- 영상 좌표 `(u, v)` [px], 목표 표적 면의 좌표 [mm], pan · tilt 각 [deg] 을 씁니다. 세 좌표계의 그림 하나를 `docs/frames.md` 에 둡니다
- px → 각도 변환 (카메라 내부 파라미터 · 렌즈 왜곡) 과 카메라–레이저 사이의 오프셋 (시차) 보정은 `src/sensing/calib.py` 한 곳에만 둡니다

**지표 (보고서의 표 머리와 같은 이름을 씁니다)**
- 추종 오차 RMS — 영상 [px] 과 표적 면 [mm] 둘 다 (변환식을 보고서에 명시)
- 명중률 — 레이저 점이 표적 중심 반지름 r [mm] 안에 든 프레임 비율 (r 은 §0 에서 고정)
- 영상→구동 지연 [ms] — LED 점멸 등으로 **측정**합니다 (카메라 FPS 로 추정하지 않습니다)
- 처리 FPS 실측 (평균 · 최소), 검출 실패 프레임 수

**안전 (STRICT)**
- 레이저는 과목 안전 공지가 허용한 모듈만 씁니다. **사람 · 눈높이 방향으로 조준하지 않고**, 표적 뒤에 빛을 막는 판을 둡니다
- 레이저 출력은 소프트웨어 interlock 뒤에 둡니다: 기본 OFF → 「표적 검출됨 + 조준 각이 작업 영역 안 + 사람이 arm 스위치를 켬」 일 때만 ON
- 에이전트는 레이저를 켜는 명령을 직접 실행하지 않습니다 (§3-1). 시험은 레이저 대신 LED 로 먼저 합니다
- pan · tilt 한계는 `hw/limits.py` 에만 두고, 한계 밖 명령은 잘라 내고 경고를 남깁니다

**흔한 함정**
- 자동 노출 · 조명 변화로 색 임계가 무너집니다 → 노출 · 게인을 고정하고 실제 값을 로그에 남깁니다 (§4-4)
- 카메라 버퍼에 쌓인 **오래된 프레임**을 처리해 지연이 커집니다 → 최신 프레임만 쓰고, 프레임 타임스탬프를 남깁니다
- 레이저 점 자체가 표적처럼 검출됩니다 → 검출 단계에서 레이저 색을 제외하거나, 레이저 OFF 프레임에서 검출합니다
- 모션 블러 · 롤링 셔터 → 노출 시간 값을 기록하고, 빠른 표적 실험에서는 따로 보고합니다
- **Pi 3 B+ / 4 의 처리 성능**: 해상도를 낮추고 (예: 320×240) 프레임당 처리 시간을 측정합니다. 처리 FPS 가 카메라 FPS 보다 낮으면 지연이 쌓입니다

**로그 필드 (최소)**: `t, tick, frame_ts, u_px, v_px, detected, pan_deg, tilt_deg, laser_on, proc_ms`
